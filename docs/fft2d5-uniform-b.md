# FFT2D5 uniform-field tracking regressions

The two self-contained cases preserve the accepted thin-ellipsoid benchmark from
OPALX commit `fd6ba8dc5`. They are actual OPALX tracking runs, separate from the
solver's C++ unit tests.

| Case | Space charge | Tracking and source |
|---|---|---|
| `FFT2D5-UniformB-ZeroSC` | Disabled with `TYPE=NONE` | 98,304 quiet protons, 128 steps, one half-turn |
| `FFT2D5-UniformB-1pC` | FFT2D5, 1 pC | Identical source and external field; mesh 128x256x1024 |

The centroid has beta=0.01 and radius 1 m in a constant 31.297388 mT field.
Initial radial, tangential and vertical semiaxes are 5, 50 and 0.5 mm. The source
has rigid-corotation velocities and no thermal spread. The physical xy/Bz
experiment is represented by the proper rotation `(x,y,z)->(x,z,-y)` in OPALX.
The bunch spans about 5.7 degrees at one instant while its centroid covers 180
degrees. FFT2D5 uses the existing OPEN longitudinal approximation, g=6.36.

The zero-space-charge control retains nominal 0.1 pC so macro charge/mass stays
finite. Its field solver is disabled; its expected STAT charge is therefore
0.1 pC, not zero. The same particle file is included in both cases so either
test directory can be copied and run independently. Identical large files have
identical Git blobs.

## Independent checks at every step

Each `validate.py` checks all 128 STAT rows, the exact particle count, assigned
charge, every expected physical time, and all three total RMS sizes against the
independent model with a 1% relative threshold. A truncated run cannot pass.
The model's full covariance is projected onto the actual moving reference axes
using each row's reference momentum. Runtime validation uses only the Python
standard library.

`analytic_covariance.csv` is generated by `make_analytic_reference.py`, which
integrates the cold uniform-volume affine ellipsoid equations with SciPy DOP853
and Carlson depolarization integrals. It never reads OPALX output and uses no
fitted charge, time or g-factor. The model source is frozen from the OPALX
benchmark commit. `analytic_provenance.json` records generator settings, energy
and angular-momentum checks, and model/config/table hashes. The validator also
checks the particle, map and path fixture hashes.

The three `.rt` last-row RMS checks compare against the native generated
reference. They complement the independent all-step validator; they do not
replace it. Their `1E-5` thresholds use the existing runner's relative-error
interpretation. Exact source fixtures avoid random-pool sampling differences.

The total-RMS criterion is deliberately distinguished from the relative error
in a small space-charge growth increment. At 1 pC the total tangential RMS error
is about 0.38%, while the charged-minus-zero tangential increase differs by about
32%. These fixtures do not claim 1% accuracy in every collective increment or
in arbitrary curved bunch geometries.

## Running

Use a build containing the FFT2D5 frame and integrated-kernel fixes. Both cases
require one MPI rank; four OpenMP threads are the local default. From a disposable
copy of a case directory:

```sh
export OPALX_EXE_PATH=/path/to/opalx/build-omp/src
export OPALX_PYTHON=/path/to/python3
./FFT2D5-UniformB-1pC.local
```

Each maintained `.local` launches OPALX and then the validator. The independent
check can also be applied to an existing output without rerunning tracking:

```sh
python3 validate.py --stat /path/to/FFT2D5-UniformB-1pC.stat \
  --output /path/to/physics-validation.json
```

`validate.py` returns nonzero on any failed physics/completeness/fixture check.
It also writes a machine-readable result if `--output` is supplied. Regenerating
the independent model table requires numpy, scipy, pandas and matplotlib via
`python3 make_analytic_reference.py`; a normal regression run does not.

## CI integration boundary

The case directories are discoverable by the existing regression scan. The
maintained local launchers enforce the full independent check. A runner that
launches OPALX directly and only interprets `.rt` files must additionally invoke
the test-local `validate.py --stat <output.stat> --output <result.json>` hook.
The existing `.rt` language's `last`/`avg` operations cannot express the complete
per-time-step criterion. A last-row-only CI run must not be reported as having
passed the independent all-step validation. The OPALX smoke-runner integration
is maintained in the OPALX repository, separately from these fixtures.

## Reference generation and validation

Native references are generated using the existing `bin/makeReference.sh --ranks
1` in private copies, with the reviewed OPALX binary and four OpenMP threads.
Only its generated `.stat` and checksum are retained in `reference/`; neither is
hand-edited. `reference_provenance.json` records the executable and input hashes,
and `reference_validation.json` records the independent validation result.

The validator was also checked with disposable outputs containing an erroneous
intermediate RMS sample, a missing final row, one missing particle, changed
charge, changed time and a nonfinite RMS value. All must fail. The intermediate
RMS mutation preserves the last-row RMS values, demonstrating why the
test-local hook is necessary in addition to the `.rt` checks.

These checks can be repeated without another OPALX run:

```sh
python3 bin/check_fft2d5_validator.py
```

The script requires a passing generated reference as its positive control and
rejects all six mutated copies. It never modifies the stored reference.

CPU/OpenMP validation is recorded here; CUDA/HIP execution has not been checked.
No 10 pC result is registered as a passing regression by these two cases. The
separate higher-charge study must first establish its accuracy and domain.
